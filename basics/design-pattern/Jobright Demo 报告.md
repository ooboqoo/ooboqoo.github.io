# Jobright Demo 报告

## 任务分析

问题定义：根据已有结构化的用户数据，帮助用户自动填写 Greenhouse 页面岗位申请表单。

技术分析：需要开发浏览器插件实现该功能。

开发环境：作业已提供基于 plasmo 的浏览器插件开发脚手架，修改实时热更新，确保了开发和调试效率。

交付预期：代码 + 实际运行录屏

### 任务细节分析

实现以下功能
1. 爬取所有表单数据
2. 根据提供的 Mock 数据，完成表单填写
	2.1 类型需要支持 「文本输入框」和「下拉列表选择」两种类型
	2.2 需要支持「教育经历」相关内容填写
3. 统计填写情况，并在浏览器控制台打印

### 效果验证

使用两个链接实际测试填写效果。



## 交付情况

交付物
* 本说明文档
* 实际运行效果录屏
* greenhouse.ts 代码

### 任务完成情况

基本任务已全部实现：
1. 支持爬取表单数据，并在控制台输出表单统计信息
2. 支持填写 「文本输入框」和 「下拉选择框」
3. 填写「教育经历」模块
4. 输出统计信息

### 后续待优化项

* 功能完善：
	* 「教育经历」部分的 School 字段，比较特殊，列表项是懒加载的，然后用的第三方组件待确认，对本次 Demo 完成影响很小，ROI 过低，暂时先跳过
	* 其他待细化验证的功能和异常情况处理
* 代码梳理优化
	* 技术点已实现，但代码结构需要重构优化，便于后续维护拓展
	* 「教育经历」部分，发现都是非标的实现，就 case by case 手撸了填充逻辑，后续可以考虑进行通用化改造（也许 never）
* 方案
	* 当前策略是针对不同网站 case by case 写适配器，没有通用性，工作量大且开发体验相当无聊，需要调研更好的方案，如直接通过 API 提交、利用 AI（Browser Use）等智能填写表单 等



对我们的业务不是很熟悉，可能需要分层去解决这个问题。大概能想到的

适合自动填写（一键自动申请）的场景
* 如果有 API 可以调，直接调 API 提交 （具体有 抓包、商务合作 等形式）
* 利用自动化测试工具，用客服等非程序员岗位去 case by case 示教，实现自动填写
* 利用 Browser Use 等新型 AI 工具去填写（相当烧 token，效果不一定好，但应该是未来重要方向）

辅助填写（就像我们刚写的这个 Demo）
* 对于大型的网站，可以上程序员 case by case 去写适配器
* 对于一般网站，fallback 到一套通用代码，能填多少是多少，反正最后都是用户自己兜底
